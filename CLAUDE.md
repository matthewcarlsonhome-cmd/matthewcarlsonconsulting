# CLAUDE.md

Matthew Carlson Consulting website. Positioning: **AI Solutions Engineer**. Background plan: `docs/AI-SOLUTIONS-REPOSITIONING-SPEC.md` (implemented October 2026).

## Stack and deploy
- Static HTML/vanilla JS in the repo root. All styles live in `css/site.css` (design tokens at the top, dark mode via `prefers-color-scheme`). Shared behavior is in `js/main.js`; the assistant chat is in `js/ai-bot.js`.
- `api/ai-chat.php` (SkillEngine Assistant: Claude Sonnet 5.5 (with server-side refusal fallback) via the Messages API over curl, streamed, last 12 turns of memory, site knowledge loaded from `llms-full.txt`, private JSONL log in a `chat-logs` folder above the web root) and `send-mail.php` run on GoDaddy Apache. `api/config.php` holds `ANTHROPIC_API_KEY` and exists only on the server (template: `api/config.example.php`). Redirects and the 404 page are configured in `.htaccess`.
- Deploy: `bash scripts/package.sh` builds `deploy/`, which is uploaded with FileZilla per `DEPLOYMENT.md`. Add any new public file to the list in `scripts/package.sh`.
- No build step. Don't add frameworks or bundlers.

## Rules
- Nav and footer live in `partials/`. Edit them there, then run `python3 scripts/sync-partials.py`. Never hand-edit between the `NAV`/`FOOTER` markers.
- Every page keeps a `<title>`, meta description, canonical and OG tags. Every visible FAQ has a matching FAQPage schema entry.
- Metrics and project facts come only from Matthew's skills reference files. Never invent numbers. Keep each item's status word (Live, Pilot, Tested, Delivered, Shipped).
- **No named clients.** Describe them generically ("a marketing agency", "a healthcare IT consultancy", "a multi-location retailer"). Past employers (Duluth Trading, Epic Systems) may be named. No client screenshots.
- Retired positioning stays retired: no Google Shopping/feeds, Meta DPA, Performance Max or n8n services. Google Ads appears only as reporting and optimization automation.
- Voice: first person, plain and specific, numbers with units. Avoid "revolutionize", "unlock", "cutting-edge" and "seamless".
- When projects change, update `projects.html` and `llms.txt`, then run `python3 scripts/build-llms.py`. The assistant reads `llms-full.txt`, so it picks up the change automatically.
- Work page case-study diagrams are inline SVG generated by `scripts/work_diagrams.py` (`render(case_id)` returns the SVG and caption); edit the node data there and paste the output into `projects.html`. Category colors are the `--cat-*` tokens in `css/site.css`.
- Insights articles live in `scripts/build-insights.py` (one dict per article: title, hook, summary, numbers, diagram key, Q&A, body HTML). Add an article there, run `python3 scripts/build-insights.py && python3 scripts/sync-partials.py`, add the page to `scripts/package.sh`, `scripts/build-llms.py`, `scripts/build-demo.py`, `sitemap.xml` and `llms.txt`. Pages under `insights/` use root-absolute asset and link paths.
- `ai-readiness-checklist.html` is a static page; scoring lives in `js/main.js` (five areas x four questions, five points each).
- `llms.txt` is hand-written; `llms-full.txt` is generated. After any page content change run `python3 scripts/build-llms.py`, which rebuilds `llms-full.txt` and fails if a link in `llms.txt` points at a missing page or anchor. Never edit `llms-full.txt` by hand.
