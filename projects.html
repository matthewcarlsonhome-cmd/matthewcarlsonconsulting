LiveAI agents · Marketing agency · 2026

Multi-agent client intelligence platform

One structured, sourced memory of every client, shared by 33 AI agents and reachable from Claude through an MCP server.

33specialized AI agents
39client profiles in production
8 toolsin the MCP server
~$32–42per month to operate

The problem

Every AI output at the agency started from a blank prompt. Client facts lived in people's heads and drifted, so content came back generic or wrong.

Results

Commercial alternatives run $49–249 per user per month; this runs the whole agency for about $32–42. Its QA engine has generated 1,504 field-level suggestions for human review.

What I built

  • A 26-section client schema with field-level provenance
  • 33 agents reading from that shared memory
  • A prompt library with versioning: 92 prompts, 94 tracked versions
  • A document layer with embeddings, and a CRM integration that has cataloged 2,590 assets
  • An MCP server with token auth and audit logging

Stack

  • TypeScript
  • Supabase / Postgres
  • Claude API (tiered model routing)
  • MCP
02
TestedAI agents · CRM · Marketing agency · 2026

Agents that build: CRM construction from a spec with Claude & Codex

AI coding agents built a marketing agency's CRM systems directly inside the platform from written specifications, verified at every step.

3.5 hrsunattended Codex build run
351custom values built in two days
10workflows built by Claude from spec
<1 minfirst lead response in testing

The problem

Each CRM template (pipelines, workflows, fields, emails, knowledge base, pages) took contract builders weeks at about $500 per template, and quality varied.

Results

A two-day build produced 351 custom values, 20 tags, 21 fields, a 12-stage pipeline, 2 calendars, a 52-entry knowledge base, 11 workflow shells, 28 SMS snippets and 4 pages. The agency put contractor hiring on hold.

What I learned

The platform's own AI created data objects but not workflows, so the agents worked in the workflow builder instead. The specification and the gap report are the real product.

What I built

  • A specification format that defines every CRM object
  • A build method where Claude or Codex constructs those objects in the live platform
  • API readback and a gap report after each phase
  • Hard boundaries: test locations only, repeated location checks, no live SMS until a compliance-safe number exists
  • A QA skill that enrolls test contacts across workflows (23 enrollments across 16 workflows)

Stack

  • Claude Code
  • OpenAI Codex
  • GoHighLevel API v2
  • Python
03
TestedVoice AI · Multi-location retailer · 2026

Inbound voice AI agent family

Phone agents that answer, qualify, book and hand off, tested against 50+ cases before any client demo.

11 / 11first test block passed
50+test cases plus a stop-ship regression
6service branches with matched follow-up texts
5phone agents and a website voice pilot

The problem

A retailer with several showrooms was missing calls and wanted every caller qualified and routed, without an AI that quotes prices or gives risky advice.

Results

Showroom booking verified on a live call. Defects found in testing, including an emergency response that could be interrupted, were fixed before the client heard the agent. Pricing proposed as a launch fee, a prepaid build and monthly maintenance, with usage at cost.

What I built

  • An agent that books appointments, takes messages and transfers with a spoken summary
  • A prequalifying flow: full questions for shoppers, two at most for service calls, immediate transfer on request
  • Consent-gated follow-up texts sent two minutes after the call, matched to the caller's need
  • Safety rules: no prices, chemical advice or promised dates; the 24-hour number on safety issues

Stack

  • GoHighLevel Voice AI
  • Conversation AI
  • CRM workflows
04
LiveReporting · Marketing agency · 2026

Account health dashboard & alert bridge

Every client CRM account checked nightly; problems become tasks in the tool account managers already use.

18health flags per account
Nightlyread-only check of every account
9,600open deals analyzed across 27 accounts
~1 weekfrom start to live

The problem

Account managers checked client accounts by hand. Silent forms, waiting leads and stalled deals surfaced only when a client complained.

Results

The first portfolio read found 81% of 9,600 open deals idle for over 30 days. The fix was three habits (closing deals out, marking losses, clearing dead deals), not a pipeline redesign.

What I built

  • A Python engine that reads every account through read-only tokens into Supabase
  • Flags compared against each account's own baseline and against peers
  • A severity-sorted view by account manager with a one-click weekly client update
  • An alert bridge that creates CRM tasks and emails for silent forms, dropped lead sources and stalled pipelines
  • A Monday digest: every open issue per client in one email

Stack

  • Python
  • Supabase
  • GoHighLevel API
  • HTML email

PilotCRM automation · AI agents · 2026

Research-then-verify client onboarding

AI researches a new client before kickoff, and the client corrects a pre-filled profile instead of filling out a long questionnaire.

26sections in each AI research profile
<20 minunattended research run
74fields covered by an automated save test
7tabs in the client onboarding app

The problem

Onboarding asked clients for hundreds of fields across long forms. Clients stalled, data arrived incomplete and launches slipped.

Results

In pilot with the agency team. Three client pilots must pass a written checklist before any new features are added.

What I built

  • A CRM workflow that fires a webhook; a Claude agent researches the business and posts a report back into the CRM
  • Research that works without a website, using license records, permits and directories
  • Stop-and-notify when a listed site is broken or belongs to another company
  • A confidence label on every field (verified, derived or needs input), and a client review and e-sign flow
  • Automatic sub-account build when onboarding completes

Stack

  • Claude Routines
  • Firecrawl
  • GoHighLevel API & webhooks
  • Supabase Edge Functions

LiveAI agents · Enablement · 2026

104-skill AI library & orchestration pipeline

An agency's AI work packaged as versioned, searchable skills, plus a one-prompt pipeline that runs nine of them in a gated sequence.

104packaged skills across 12 categories
9skills in one gated pipeline
17deliverables per pipeline run
~$4–8measured cost per run

The problem

Good prompts lived in individual chats. When one early run scaled 43 outputs from an unchecked source, 22 of them had to be regenerated.

Results

The library is published as a searchable site with team and priority filters, so each team starts from an adopt-first list.

What I built

  • A versioned skill plugin with a manifest for team rollout
  • A pipeline that builds a source document, validates and freezes it, then runs parallel steps from it
  • Gates before scale: a validator, a graded voice sample and a capacity check
  • A quarterly library audit for duplicates and retirement

  • Firecrawl
  • Netlify
